**2. 论文和历史实现必须分开理解**

全文描述了三部分：LLM 抽取、实体归一、图补全。Figure 3 给出加权属性相似度、特征覆盖和时间项的组合；Figure 6 则按后续文献报道验证预测。Darwin 的抽取指标不能用于判断我们的检索模型优劣；文中“九年内 48.5%”也不是实验成功率或机制迁移准确率。[正式全文，§2–3、Figure 3/6](https://proceedings.neurips.cc/paper_files/paper/2024/file/680da2fd0331deecc2e5b7cf0e55e832-Paper-Conference.pdf)

历史 notebook 实际使用的核心分数如下（按代码归纳）：

`score(m,a) = max_{u 已用于 a} J(F(m), F(u)) × max_{b 为 m 的已有应用} J(P(b), P(a))`

其中 `F` 合并材料的 `hasStructure/Phase` 与 `hasProperty` 邻居，`P` 是应用的 `hasProperty` 邻居，`J` 为集合 Jaccard。实现要求候选材料与参与比较的已知材料至少有 5 个特征。它是在“与目标应用中已知材料相似”和“现有应用与目标应用相似”两个方面共同寻找联系。这里的两个最大值可能来自不同的比较对象。

这份实现没有提供 Figure 3 的完整加权 S/F/T 组合、时间衰减和参数搜索。代码建立 `evalapp` 后未继续给出后续报道命中率计算；也缺少 `create_triples`、`clean_triples`、`DOI_Year`、`NERoutput` 等定义/输入。因此：可以借鉴、恢复局部方法，不能声称已经复现论文曲线。

本次两个最小合成检查说明了直接套用的风险：

- 两材料具有完全相同的 5 项属性，但应用属性为空，乘积分数不给候选；补上共享应用属性后才得到分数 1。缺失信息在该实现中会直接使分数为零，不能将零分解释为物理不兼容。
- 它使用 `nx.Graph`：同一对节点上的不同方向/类型关系可被覆盖。这不适合我们保留谓语、方向、条件和证据的多关系机制图。

上游还只在 Formula 节点中取候选，末尾排除部分应用名称并按字符串检查历史摘要。对我们，必须单独记录适配覆盖率、未评分原因；不能照搬这些规则来删减默认语料，也不能把字符串无命中当作无先例。

**4. 怎样具体跟进他们的 GitHub**

推荐增加一个独立的“按属性寻找相似已知方案”比较分支，接在现有证据图旁边：

`TG 需求及既有方案 → 方案依赖的过程/属性 → iTE 调控关系及支持证据 → 兼容性核查 → 可检验假设`

它借鉴历史 notebook 的“目标已有材料”和“应用属性”两侧比较，但我们的比较对象应明确为材料、干预、过程或证据关系，不能混为同类节点。映射表需记录 `claim_id`、论文、原表达、比较类型；有依据才连桥接关系，保留两领域身份，不强行跨域合并。

准备两条分数路线：

1. **历史代码逻辑基线**：在明确映射后的属性集合上计算其双 Jaccard 乘积；保留 Formula/特征数等适用条件的覆盖统计。标记为“历史代码逻辑的适配”，不要称正式论文完全复现。
2. **机制关系适配版**：比较有类型的干预、过程、对象和效果，方向冲突单独标记；属性缺失记为未知。它是我们的扩展，需要消融验证，不能把设计出的权重归给作者。

专家词典可以用于提出同义候选，但上游 ER 会删除某些未达到阈值的表达，并有宽泛 `except: continue`。我们的未匹配表达应保留并标待核。化学名/缩写校验可选用 mat2vec + ChemDataExtractor；机制句子的含义不应通过词向量均值替代。mat2vec 是词向量方法，不是 Transformer。

暂不优先重建 Neo4j 或重新微调 Darwin。现有 JSON 图已能支持本轮对照；数据库换型本身不能修复反向关系召回。抽取阶段已冻结，不因参考文献出现而自动重启。

**5. Transformer 要不要换**

答案是：保留 MiniLM 作基线，值得比较少量明确分工的模型；现在没有证据指定某个新模型必胜。论文中的 LLaMA/Darwin 负责生成实体/关系，TransE 负责图嵌入；二者都不是当前 MiniLM 句向量检索的直接等价替换。

| 角色 | 第一轮选择 | 为什么试、怎样使用 |
|---|---|---|
| 当前句向量基线 | `sentence-transformers/all-MiniLM-L6-v2` | 复现当前结果，并隔离“改流程”本身的收益；当前缓存只发现这一模型 |
| 检索编码器候选 A | `BAAI/bge-base-en-v1.5` | 测试为检索设计的表示；英文短查询按模型卡加 query instruction，正文不加同样指令 |
| 检索编码器候选 B | `intfloat/e5-base-v2` | 独立的 query/passage 检索模型路线；必须按模型卡加 `query:` / `passage:` |
| 成对重排 | `BAAI/bge-reranker-v2-m3` | 对候选 query+evidence 联合打分；它是相关性重排器，不是科学因果或蕴含证明器 |
| 材料实体辅助（可选） | mat2vec | 对齐上游 ER 的材料术语层；评估同义名、缩写等覆盖，不用于替代整句需求检索 |

模型依据：[MiniLM](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2)、[BGE](https://huggingface.co/BAAI/bge-base-en-v1.5)、[E5](https://huggingface.co/intfloat/e5-base-v2)、[reranker](https://huggingface.co/BAAI/bge-reranker-v2-m3)、[mat2vec 官方代码](https://github.com/materialsintelligence/mat2vec)。推荐是任务匹配与实验成本方面的判断，不是本语料实测排名。

MatSciBERT/MatBERT 的领域预训练有价值，但“材料领域 BERT”不自动等于训练好的句子检索器；不能直接均值池化后宣称胜过 MiniLM。若后续要做领域适配，可用独立标注的机制正负例进行对比学习后再测。[MatSciBERT 官方实现](https://github.com/M3RG-IITD/MatSciBERT)

SPECTER2 可作为标题+摘要级论文召回的后备实验，其文档表示目标不同于当前短机制关系；本轮先不扩大模型数量。[官方模型卡](https://huggingface.co/allenai/specter2)

**6. 比较怎样才有意义**

首轮做三个编码器的受控比较，再给最好的候选检索路线加一次 cross-encoder 重排。不先集成所有模型，不比较它们的余弦绝对值，不用同一个旧 MiniLM top-200 判断所有新模型的召回能力。

建议实验阶梯：当前流程 → 同 MiniLM 的全关系/混合召回 → 相同流程分别换 BGE、E5 → 在冻结候选池上比较重排 → 加入历史 MKG 属性分支 → 加入方向/对象兼容性检查。每一步独立报告，区分编码器变化和流程变化。

当前 4 个需求和 42 项已审查记录适合回归诊断，不是独立 gold。应汇总各检索路线的候选、加入同词反义/不相关/已在 TG 实现的困难样例，并由领域人员对模型来源盲评。可从约 200–400 个 query–claim 样例起步，随后扩展有文献锚点的新需求并留出。评估单位同时保留 claim 和 paper，避免同论文多条边充当多个独立样本。

至少分开评价：

- 需求相关性及已标正例的 Recall@50/200；标注不穷尽时只能叫“已知正例召回率”。
- 文献/机制相关性的 nDCG@10、人工审查前 5 篇的有效项数，以及相反作用误召回率。
- 原证据是否支持该干预与作用、是否仅为模型解释、是否依赖联合因素、目标物种与体系是否适用。
- TG 已有方案识别能力；在当前 TG 库中无命中只表示未检出，不能自动标全局新颖。
- 实际耗时、内存、截断率、未评分覆盖率；审查工作量也计入成本。

只有 4 个需求时，不宜用边数放大样本量或报告稳健的跨需求显著性。扩大样本后，以需求/论文为分组单位做留出和不确定性统计。历史的助手判断用于定位错误，不充当独立专家评价。

时间回溯值得借鉴，但应放在以上小规模比较之后：先按年份切断输入论文和证据边，再建立词典/索引/候选；训练、调参、测试时间窗分离；检查测试前是否已有目标应用。现代预训练模型可能见过晚于截断年的文本，若无法排除，应称“历史文献回溯检索”，不要称严格前瞻预测。晚期未报道的候选记为未验证，不自动认定物理失败。

可执行顺序已固化为 [benchmark_spec.json](benchmark_spec.json)。它是待执行的实验契约，不是已跑出的 benchmark 结果。

**7. 补充的复现边界**

- 发布数据实际有 TrainSet1.0 562 行（497 个唯一 input）、TrainSet2.0 90 行（90 个唯一 input）、Name/Formula 分类 1,801 行；两个 NER 版本存在 31 个完全相同的 input。README 说从 v1 取一部分评价，但未指定具体子集。因此必须自行保证 train/dev/test 不交叉；不能据这 31 项就指控论文评价泄漏。
- ER notebook 引用 `./dictionary/abbreviation.xlsx`、中间结果和本地模型路径；当前仓库没有提供全部对应路径下的文件。历史图补全也依赖 notebook 外变量，所以它们是方法参考，不是即开即跑的端到端包。
- 当前推理脚本使用随机采样而未见设 seed；工作进程的分片文件每 10 项刷新，尾部不足 10 项未单独刷新，但主进程正常结束时会汇总 shared_results。应区分分片恢复风险与整体正常输出，不能笼统断言丢掉全部尾部数据。
- 本轮没有运行上游全数据实验，也没有把论文的准确率或本项目历史指标冒充当前 corpus 的重算结果。

最值得立即做的是：先修编码缓存与全关系召回，再用三种编码器作同任务比较；以历史 GitHub 的双侧属性比较作为独立基线，保留我们已经建立的原句、方向、联合因素和目标已有工作证据层。
